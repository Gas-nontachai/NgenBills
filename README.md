# เงินบิล — NgenBills 🌱

แอป Flutter สำหรับติดตามหลายบัญชีหนี้ ใช้งานออฟไลน์ ไม่มีบัญชีผู้ใช้หรือ backend ข้อมูลหนี้และรายการจ่ายเก็บใน SQLite ภายในอุปกรณ์ ฟอนต์ Kanit รวมไว้ในแอปแล้ว

MVP: เพิ่มหนี้ ปรับแต่งชื่อ/ไอคอน/สีบัญชี กู้เพิ่มพร้อมประวัติ ลบบัญชีหลังยืนยัน ดูยอดคงเหลือและกราฟครึ่งวงกลม บันทึกการจ่ายพร้อมวันที่และหมายเหตุ ดูประวัติ/รายละเอียด ลบหลังยืนยัน และแสดงสถานะชำระครบ 100% รองรับ Android และ iOS ภาษาไทย พร้อมตั้งแจ้งเตือนวันชำระหนี้ประจำเดือน

## เริ่มใช้งาน

ต้องติดตั้ง Flutter stable ที่รองรับ Dart 3.13.5 หรือใหม่กว่า พร้อม Android SDK หรือ Xcode

```sh
flutter pub get
flutter run -d <device-id>
```

Android application ID และ iOS bundle identifier: `com.gasnontachai.ngenbills`

## ตรวจสอบ

```sh
flutter analyze
flutter test
flutter build apk --debug
flutter test integration_test/app_flow_test.dart -d <android-device-id>
```

Integration test ใช้ฐานข้อมูลทดสอบแยกไฟล์และลบหลังจบ ไม่แก้ข้อมูลจริงของแอป ทดสอบสร้างหนี้ จ่ายบางส่วน เปิด SQLite และสร้าง app state ใหม่ ลบรายการ จ่ายครบ ปรับแต่งบัญชี กู้เพิ่ม เปิดฐานข้อมูลใหม่ ลบกู้เพิ่ม และลบบัญชีแล้วสร้างใหม่โดยไม่แสดง onboarding ซ้ำ

Widget tests มีภาพอ้างอิงใน `test/goldens/` สำหรับหน้าจอสำคัญ หากตั้งใจปรับดีไซน์ให้ใช้ `flutter test --update-goldens` แล้วตรวจภาพใหม่ก่อนยอมรับ ภาพ baseline ของ macOS อยู่ใน `test/goldens/` และของ Linux runner อยู่ใน `test/goldens/linux/` เพื่อเปรียบเทียบกับ renderer ของระบบเดียวกัน

## โครงสร้างและข้อมูล

- `lib/app`: GoRouter, theme และ design tokens
- `lib/core`: SQLite schema, formatters, error handling และ reusable widgets
- `lib/features/debt`: debt repository, summary/domain logic, Riverpod providers และหน้าจอ
- `lib/features/payment`: payment repository, ประวัติ และ bottom sheets

จำนวนเงินจัดเก็บและคำนวณเป็น integer satang; `0.01` บาทคือ `1` สตางค์ ไม่มี floating-point ในการรวมยอด ยอดหนี้รวม = ยอดตั้งต้น + ยอดกู้เพิ่ม และยอดคงเหลือ = ยอดหนี้รวม − ยอดจ่าย เปอร์เซ็นต์ชำระใช้ยอดจ่ายหารยอดหนี้รวม ไม่เก็บยอดรวมเป็นค่าที่เปลี่ยนแยกกันได้ การเขียนข้อมูลใช้ transaction และตรวจยอดคงเหลือภายใน transaction เพื่อป้องกันการจ่ายเกินยอด การส่งซ้ำใช้ shared action lock

SQLite schema version 1 เริ่มนับใหม่ก่อน release รวมตารางหนี้ รายการจ่าย กู้เพิ่ม การแจ้งเตือน และ app preferences ใน schema เริ่มต้นเดียว บัญชีใหม่ใช้ไอคอนกระเป๋า/สีเขียวเป็นค่าเริ่มต้น เปิด foreign keys และมี index ตามหนี้/วันที่ รองรับหลายบัญชีโดยแยกประวัติด้วย debt_id เก็บบัญชีหลักใน app_preferences และเติมค่าให้ข้อมูลเดิมโดยไม่ล้างฐานข้อมูล Timestamp เป็น UTC และวันที่จ่าย/กู้เพิ่มเป็น local date-only (`YYYY-MM-DD`) หน้าจอแสดงวันที่ภาษาไทย/พ.ศ.

ไม่มี migration จาก build ทดลองก่อนหน้า หากเคยติดตั้ง build เดิม ให้ล้างข้อมูลแอปหรือถอนการติดตั้งแล้วติดตั้งใหม่เพื่อสร้างฐานข้อมูล version 1 ชุดใหม่ (ข้อมูลทดลองบนเครื่องนั้นจะถูกลบ) แอปไม่ล้างฐานข้อมูลเดิมอัตโนมัติ เมื่อเริ่ม release ที่มีผู้ใช้จริง ให้เพิ่ม migration สำหรับการเปลี่ยน schema ครั้งต่อไป

ยังไม่รองรับการแก้ยอดตั้งต้น การแก้ไขรายการจ่าย/กู้เพิ่ม หรือ cloud sync ในรุ่นนี้

## Settings และ Backup/Restore

ก่อนสำรอง แสดงรายการข้อมูลที่รวมในไฟล์และนโยบายการจัดเก็บ พร้อมลิงก์อ่านนโยบายความเป็นส่วนตัวแบบออฟไลน์ เริ่มสร้างไฟล์เมื่อกด “สำรองและเลือกที่บันทึก” เท่านั้น ส่วนหน้าตรวจสอบก่อนกู้คืนแสดงชื่อไฟล์ วันสำรอง จำนวนบัญชี/รายการ และการตั้งค่าที่นำกลับมา พร้อมย้ำผลของการแทนที่และสิทธิ์แจ้งเตือนของเครื่อง

ปุ่มตั้งค่าบนหน้าหลักและหน้าว่างเปิด `/settings` แยกหมวดข้อมูล การแจ้งเตือน และเอกสารเกี่ยวกับแอพ หน้าแจ้งเตือนเดิมยังอยู่ที่ `/settings/notifications`

สำรองข้อมูลด้วยตัวเลือกไฟล์ของระบบเป็น `ngenbills_YYYYMMDD_HHmmss.ngenbills` รวมทั้ง 5 ตารางใน snapshot transaction เดียว: debts, payments, borrowings, reminder_settings และ app_preferences ไฟล์เป็น JSON UTF-8 แบบไม่เข้ารหัส ไม่มีรหัสผ่าน และไม่มีการอัปโหลดจากแอพ รองรับขนาดไม่เกิน 32 MiB โดยระบุ app, formatVersion, schemaVersion, createdAt และ data ปัจจุบันรองรับ format/schema version 1

การกู้คืนตรวจโครงสร้าง เวอร์ชัน ชนิดข้อมูล วันที่ ID ความสัมพันธ์ ยอดรวม และบัญชีหลักก่อนให้ยืนยัน แสดงวันสำรองและจำนวนบัญชี/รายการ แล้วแทนที่ทุกตารางใน transaction เดียว ไม่ merge หากผิดพลาด rollback ทั้งหมด รองรับไฟล์ว่าง การกู้คืนใช้ shared action lock และคิวแจ้งเตือนเดิม หลังสำเร็จรีเฟรชข้อมูล เลือกบัญชีหลักจาก backup และจัดตารางเตือนใหม่ตามสิทธิ์ของเครื่อง หากจัดตารางเตือนไม่สำเร็จ ข้อมูลที่กู้คืนสำเร็จยังคงอยู่และมีช่องทางลองจัดตารางใหม่

ข้อกำหนดการใช้งานและนโยบายความเป็นส่วนตัวภาษาไทยอ่านแบบออฟไลน์ได้ใน Settings ฉบับ 1.0 มีผล 9 ตุลาคม 2569 ผู้ให้บริการ Nonthachai Phosri ติดต่อ nontachimuraproduction@gmail.com ตัวแอพสงวนลิขสิทธิ์ตาม LICENSE ส่วนหน้า Licenses ใช้ Flutter LicenseRegistry สำหรับ dependencies และลงทะเบียน copyright/SIL OFL ของ Kanit เพิ่มจาก assets/fonts/OFL.txt หากส่งขึ้นสโตร์ต้องเตรียม URL นโยบายสาธารณะและข้อมูลความเป็นส่วนตัวของสโตร์ให้ตรงกับการทำงานจริงด้วย

แพลตฟอร์มเป้าหมายคือ Android และ iOS โดยเก็บ runner เฉพาะ `android/` และ `ios/` ไม่รองรับ Web หรือ desktop ภาพอ้างอิง Linux ใน `test/goldens/linux/` ยังใช้สำหรับตรวจ UI บน CI และไม่ได้หมายถึงการรองรับแอป desktop

## แจ้งเตือนวันชำระหนี้

แจ้งเตือนแบบ local บน Android/iOS ไม่ใช้ backend และไม่ต้องเปิดแอปค้างไว้ หน้า onboarding แสดงหลังสร้างหนี้ก้อนแรกสำเร็จเพียงครั้งเดียวและข้ามได้ เมื่อจบจะเข้าหน้าหลักโดยไม่เปิดตั้งค่าแจ้งเตือนอัตโนมัติ ขอสิทธิ์เมื่อผู้ใช้กดเปิดการแจ้งเตือนเท่านั้น ตั้งค่าจากแถบ Home หรือหน้า Settings ได้ เลือกวันประจำเดือน 1–31, เตือนล่วงหน้า 1/3/7 วันพร้อมกันได้หลายช่วง (หรือไม่เลือก), เวลาเป็นชั่วโมง/นาที และเตือนวันครบกำหนด ค่าเริ่มต้นของแผงตั้งค่าที่ยังไม่เคยบันทึกคือปิดเตือน (ยังไม่มีตารางเตือนจริง), วันที่ 1, ล่วงหน้า 3 วัน, 09:00 และเตือนวันครบกำหนดด้วย เปลี่ยนวันผ่านตาราง 1–31 และยืนยันได้ ค่าจะเริ่มใช้งานเมื่อกดบันทึก และขอสิทธิ์แจ้งเตือนในขั้นตอนนี้หากยังไม่อนุญาต ตารางแจ้งเตือนรวมทุกบัญชีเก็บสูงสุด 60 รายการที่ใกล้ที่สุดในกรอบ 24 เดือน และเติมใหม่เมื่อกลับเข้าแอป

เดือนที่ไม่มีวันที่เลือกใช้วันสุดท้ายของเดือน ระบบตั้งรายการแบบครั้งเดียวในกรอบ 24 รอบเดือน โดยเก็บสูงสุด 60 รายการที่ใกล้ที่สุดรวมทั้งแอป และสร้างใหม่เมื่อเปิด/กลับเข้าแอป เปลี่ยนค่า หรือเพิ่ม/ลบการจ่าย ใช้เขตเวลาของเครื่อง ณ ครั้งล่าสุดที่จัดตารางเตือน หากเดินทางเปลี่ยนเขตเวลา ให้เปิดแอปเพื่อปรับตารางเป็นเขตเวลาใหม่ จำนวนเดือนที่ครอบคลุมขึ้นกับช่วงเตือนที่เลือก ตารางจะหมดเมื่อถึงรายการสุดท้ายหากไม่ได้เปิดแอปมาเติมใหม่

จ่ายบางส่วนยังเตือนต่อ จ่ายครบยกเลิกเฉพาะบัญชีนั้น ลบการจ่ายจนกลับมามียอดค้างจะตั้งเตือนใหม่ ข้อความระบุยอดหนี้คงเหลือล่าสุดที่บันทึกในแอป ไม่ใช่ยอดขั้นต่ำหรืองวดรายเดือน เมื่อแตะข้อความจะเปิดบัญชีที่เกี่ยวข้อง หากถูกลบจะเปิดบัญชีหลักหรือหน้าว่าง สถานะเปิดเตือนในแอปและสิทธิ์ของเครื่องแสดงแยกกัน หากการจัดตารางล้มเหลว ข้อมูลยังบันทึกและมีปุ่มลองใหม่

Android ใช้ inexact alarms ไม่ขอสิทธิ์ exact alarm เพิ่ม เวลาเลือกเป็นเวลาเป้าหมายและอาจล่าช้าเพราะระบบประหยัดแบต การ force-stop, การบล็อก background ของผู้ผลิตเครื่อง หรือการถอน permission อาจหยุดการส่งเตือน Android มี boot/app-update receiver สำหรับกู้ตารางหลังรีสตาร์ต เปิดแอปเพื่อ reconcile อีกครั้งได้ iOS ไม่ต้องใช้ push entitlement หรือ APNs

ตรวจ native pending schedule บน emulator/device (ทดสอบแทนตารางแจ้งเตือนของแอปบนอุปกรณ์ทดสอบ; iOS ขอ provisional authorization หากยังไม่อนุญาต เพื่อให้ระบบยอมรับ pending requests โดยไม่แสดง prompt):

```sh
flutter test integration_test/notification_schedule_test.dart -d <device-id>
```

ก่อน release ให้ตรวจบนเครื่องจริงทั้ง Android/iOS: อนุญาต/ปฏิเสธ permission, แอปปิดตามปกติ, reboot Android, เปลี่ยนเขตเวลา, และแตะ notification ขณะแอปเปิดหรือปิด Tests อัตโนมัติครอบคลุมการสร้างฐานข้อมูลและเปิดใหม่, calendar/DST, ยอดเงิน, cancellation/retry, UI และ golden บน macOS/Linux

## Android signing และ GitHub CI/CD

- `ci.yml`: เมื่อ push หรือเปิด PR เข้า `main`/`dev` จะตรวจ release tooling, `flutter analyze` และ `flutter test`
- `android-release.yml`: เมื่อ push tag `vMAJOR.MINOR.PATCH` ที่อยู่บน `main` จะทดสอบ สร้าง signed release APK ตรวจลายเซ็น และเผยแพร่ GitHub Release พร้อม SHA256 checksum
- เวอร์ชัน release มาจาก tag; build number มาจาก workflow run number + repository variable `ANDROID_BUILD_NUMBER_OFFSET` (ค่าเริ่มต้น `1`)

Signing ใช้ release key ของ NgenBills โดยเฉพาะ ไม่มี fallback ไปใช้ debug key หากตั้งค่าไม่ครบ release build จะหยุด

Local signing ใช้ `android/key.properties` และ `android/keystores/ngenbills-release.jks` ซึ่งถูก ignore ไว้ และจำกัดสิทธิ์การอ่านเฉพาะเจ้าของ ดูรูปแบบค่าได้ใน `android/key.properties.example` **สำรองไฟล์จริงทั้งสองไว้ในที่เก็บที่ปลอดภัย และใช้ key เดิมสำหรับอัปเดตแอป** ห้าม commit ไฟล์จริงหรือใส่รหัสผ่านใน workflow

GitHub repository ต้องมี encrypted Actions secrets:

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

สร้าง signed APK ในเครื่อง:

```sh
flutter build apk --release
```

เมื่อต้องการเผยแพร่ release หลัง CI ผ่าน:

```sh
git tag v1.0.0
git push origin v1.0.0
```

เปลี่ยน tag ตามเวอร์ชันใหม่ที่จะเผยแพร่ ไม่ใช้ tag เดิมซ้ำ Pipeline นี้รองรับ Android; iOS/TestFlight signing ยังไม่ได้ตั้งค่า

## จัดการบัญชีและกู้เพิ่ม

จากเมนูสามจุดบนบัญชี เลือกกู้เพิ่มหรือปรับแต่งบัญชีได้ ตั้งชื่อได้ 1–100 ตัวอักษร เลือกไอคอน 10 แบบและสีพื้นหลังไอคอน 7 สี โดยไม่เปลี่ยนยอดตั้งต้นหรือหมายเหตุบัญชีเดิม รายการกู้เพิ่มใช้วันที่วันนี้หรือย้อนหลัง หมายเหตุไม่เกิน 500 ตัวอักษร จำนวนเงินและยอดหนี้รวมไม่เกินวงเงินเดิมของระบบ

ประวัติรายการรวมจ่ายชำระ (จำนวนติดลบสีเขียว) และกู้เพิ่ม (จำนวนบวกสีน้ำเงิน) เรียงวันที่ เวลาบันทึก และ ID ล่าสุดก่อน เปิดรายละเอียดและลบกู้เพิ่มหลังยืนยันได้เมื่อยอดหนี้รวมหลังลบไม่น้อยกว่ายอดที่จ่ายแล้ว ตรวจภายใน transaction กู้เพิ่มหลังชำระครบจะเปิดให้จ่ายและตั้งแจ้งเตือนต่อหากการตั้งค่าเดิมเปิดไว้

ลบบัญชีจากท้ายแผงปรับแต่ง ต้องยืนยันก่อนลบถาวร ทั้งยอดหนี้ รายการจ่าย กู้เพิ่ม และการตั้งค่าแจ้งเตือนจะถูกลบใน transaction เดียว ระบบปรับตารางแจ้งเตือนและกลับบัญชีหลักที่เหลือ หรือหน้าว่างเมื่อไม่มีบัญชี โดยคงสถานะ onboarding ที่เคยผ่านแล้วไว้ หากยกเลิกแจ้งเตือนไม่สำเร็จ มีข้อความและปุ่มลองใหม่บนหน้าว่าง ข้อมูลที่ลบสำเร็จจะไม่ถูกแจ้งว่าเขียนล้มเหลว

## หลายบัญชีหนี้

การ์ดบัญชีเป็น carousel เห็นขอบการ์ดข้าง ๆ เสมอ ปัดซ้าย–ขวาแล้วการ์ดเลื่อนพร้อมกันตามนิ้วและ snap เข้าตำแหน่ง ไม่วนกลับจากท้ายไปต้น แตะชื่อ ลูกศรลง หรือตำแหน่งเพื่อเปิด Bottom Sheet เลือกบัญชีพร้อมค้นหาชื่อและปุ่ม “เพิ่มบัญชี” รวมบัญชีที่ชำระครบแล้ว รายการเรียงตามเวลาสร้าง ไม่จำกัดจำนวนบัญชี ไม่มีหน้ารวมยอดในรุ่นนี้

หลังบัญชีสุดท้ายมีการ์ด “+” สำหรับเพิ่มบัญชี โดยไม่รวมในจำนวนบัญชี เริ่มจากบัญชีสุดท้าย ลากไปทางการ์ด “+” อย่างน้อย 80 logical pixels ค้าง 600 ms แล้วปล่อยเพื่อเปิดฟอร์ม ความคืบหน้าแสดงเป็นวงรอบ “+” ในส่วนการ์ดที่มองเห็น เมื่อพร้อมจะสั่นและแสดง “ปล่อยเพื่อเพิ่มบัญชี” ปล่อยเร็ว ลากกลับ ยกเลิก gesture หรือเริ่มบันทึกข้อมูลจะคืนบัญชีสุดท้ายและไม่เปิดฟอร์ม ไม่สามารถจอดบนการ์ด “+” ได้ และยังเพิ่มบัญชีจากแผงเลือกบัญชีได้

บัญชีแรกเป็นบัญชีหลัก เปลี่ยนได้ในแผงปรับแต่ง เปิด process แอปใหม่แสดงบัญชีหลัก กลับจาก background หรือหน้าตั้งค่าคงบัญชีที่ดูอยู่ สร้างสำเร็จแสดงบัญชีใหม่โดยไม่เปลี่ยนบัญชีหลัก ลบบัญชีหลักแล้วใช้บัญชีเก่าสุดที่เหลือ ลบทั้งหมดกลับหน้าว่างโดยคงสถานะ onboarding

เมื่อปัดจนการ์ดหยุด บัญชีที่เลือกจะเปลี่ยนทันทีโดยไม่รอ query เพิ่ม การ์ดและประวัติด้านล่างอ่าน summary จาก provider ของ ID เดียวกัน หากยังไม่มีข้อมูลจะแสดงกำลังโหลดหรือข้อผิดพลาดของบัญชีนั้นแทนข้อมูลเก่า Callback ของ gesture ก่อนหน้าจะไม่สั่งเลื่อนกลับหลังเริ่ม gesture ใหม่ การสลับบัญชีที่ดูไม่จัดตารางแจ้งเตือนใหม่ เพราะตารางเดิมรวมทุกบัญชีอยู่แล้ว

ฟอร์มแสดงชื่อและไอคอนของบัญชีเป้าหมาย ล็อกการสลับและส่งซ้ำเฉพาะช่วงเขียนฐานข้อมูล การโหลดใหม่และจัดตารางเตือนไม่ยืดช่วงล็อก ตั้งเตือนแยกบัญชีและปิดทั้งหมดได้จากหน้าการแจ้งเตือน บัญชีใหม่ยังไม่เปิดเตือน ตารางเติมเมื่อเปิด/กลับเข้าแอปหรือข้อมูลเปลี่ยน และอาจหมดหากไม่กลับมาเปิดแอป
